# sam2-lite

**Faster SAM 2.1 video object segmentation on CPU, by distilling its image encoder into a mobile backbone — measured end to end, with every number traceable to an MLflow run.**

> 🚧 Work in progress. Done: distillation, evaluation, latency benchmark, profiling, model registry. Next: lighter memory attention, ONNX export, Hugging Face model + Gradio demo, CI with an evaluation gate.

## The idea

SAM 2.1 tracks an object through a video from a single click. Each frame goes through three parts: an **image encoder** (Hiera), a **memory attention** that conditions the frame on previous frames, and a **mask decoder**. On CPU the tiny model takes ~2 s per frame.

sam2-lite replaces only the image encoder with a **MobileNetV4-Conv-Medium** backbone (from `timm`) plus SAM 2's own FPN neck, trained to reproduce the teacher encoder's multi-scale features (**feature distillation**, no labels needed). Because the student returns exactly the same outputs as the original encoder (same keys, levels, shapes and dtypes, enforced by a contract test), SAM 2.1's memory and decoder are reused unchanged.

```
frame ──► [ image encoder ] ──► features ──► [ memory attention ] ──► [ mask decoder ] ──► mask
           Hiera-T (teacher)                     SAM 2.1-tiny, unchanged
           MobileNetV4 + FPN (student, distilled: MSE on the 3 backbone_fpn levels)
```

## Results

Teacher: SAM 2.1 Hiera-tiny. Student: MobileNetV4-Conv-Medium + FPN neck, distilled on DAVIS 2017 *train* frames. Quality on the full **DAVIS 2017 val** set (30 videos, 61 objects, semi-supervised protocol, SAM 2's J&F evaluator).

| | SAM 2.1 Hiera-T (teacher) | sam2-lite (student) | Change |
|---|---|---|---|
| J&F (DAVIS 2017 val) | 89.1 | 84.9 | -4.2 |
| J | 85.7 | 81.9 | -3.8 |
| F | 92.5 | 87.9 | -4.6 |
| Encoder params (M) | 27.2 | 7.5 | 3.6× fewer |
| Encoder size, fp32 (MB) | 104 | 29 | 3.6× smaller |
| Whole model size, fp32 (MB) | 149 | 74 | 2.0× smaller |
| Encoder, CPU 6 threads (ms/frame) | 739 | 214 | 3.45× |
| **Full pipeline, CPU 6 threads (ms/frame)** | **1967** | **1477** | **1.33×** |
| Encoder, CPU 2 threads (ms/frame) | 1818 | 464 | 3.92× |
| Full pipeline, CPU 2 threads (ms/frame) | 4984 | 3688 | 1.35× |
| Full pipeline, GPU bf16 (ms/frame) | 69 | 49 | 1.41× |

Latency: median per frame after warmup (20 CPU / 50 GPU calls), full pipeline measured frame by frame inside SAM 2's video predictor; teacher and student measured in the same session on an Intel i7-13620H / RTX 4060 Laptop GPU, torch 2.14.1. The table is generated by `scripts/results_table.py` from MLflow runs (eval `b44efdd1` / `c27ca8b7`, latency `9dad8e53` / `575ec43c`), which refuses runs produced with uncommitted code.

**Acceptance criteria were fixed before the final results:** J&F drop ≤ 5 points and full-pipeline CPU speedup ≥ 1.25× (`configs/eval_gate.yaml`). Both are met.

### Why the full pipeline gains less than the encoder

A 3.45× faster encoder gives a 1.33× faster frame — exactly what Amdahl's law predicted from the teacher's breakdown. Profiling one frame (CPU, 6 threads) shows where the time goes:

| Component | Teacher | Student |
|---|---|---|
| memory attention | 1163 ms (58.7 %) | **1186 ms (80.3 %)** |
| image encoder | 749 ms (37.8 %) | 219 ms (14.8 %) |
| memory encoder + mask decoder + rest | 70 ms (3.5 %) | 72 ms (4.9 %) |

After distilling the encoder, **the memory attention is 80 % of the frame time** (69 % of all CPU time is the attention kernel itself: ~4k query tokens against up to 7 memory frames). Making it 2× faster would give a further 1.67×; making the encoder infinitely fast, only 1.17×. That is the next step of the project.

### What the student gets wrong

Per-object analysis (`scripts/compare_vos.py`): the J&F drop is not uniform. Three objects explain almost half of it — a tiny object (0.1 % of the image) lost after a few frames, and a rider and motorbike merged into one object in a close-up — while the other 58 objects lose ≈ 2.6 points on average. A second training run that up-weighted the fine FPN levels improved their feature error but lowered J&F (84.0): the coarse level used by the memory matters more for tracking.

## Reproduce

Requires Linux, Python 3.11 and [uv](https://docs.astral.sh/uv/). A CUDA GPU is used for training and evaluation.

```bash
make setup                     # uv sync + pre-commit hooks
make checkpoints               # SAM 2.1 Hiera-tiny weights (SHA-256 checked)

# DAVIS 2017 trainval 480p (direct download, not redistributed here)
mkdir -p data/raw && cd data/raw && wget -c https://data.vision.ee.ethz.ch/csergi/share/davis/DAVIS-2017-trainval-480p.zip && unzip -q DAVIS-2017-trainval-480p.zip && cd ../..

uv run python scripts/build_manifest.py                # train/val split by video
make train CONFIG=configs/train/night1.yaml            # ~7 h on an RTX 4060 Laptop
make eval MODEL=teacher
make eval MODEL=student CKPT=checkpoints/distill/night1/best.pt
make bench MODEL=student CKPT=checkpoints/distill/night1/best.pt
make profile MODEL=student CKPT=checkpoints/distill/night1/best.pt
make test
```

Experiments are tracked in a local MLflow database: `uv run mlflow ui --backend-store-uri sqlite:///mlflow.db`.

```

src/sam2lite/
  data/             DAVIS I/O, frame manifest, dataset with SAM 2's exact preprocessing
  models/           student encoder (timm trunk + SAM 2 FpnNeck)
  train/            distillation loss and resumable training loop
  eval/             VOS inference, J&F (vendored SAM 2 evaluator)
  bench/            latency benchmark and per-component profiling
  tracking.py       MLflow helpers (config + git commit on every run)
scripts/            one-off entry points (checkpoint download, analysis, result table, registry)
tests/              contract, preprocessing, loss, data and tracking tests (no dataset needed)
```

## Engineering notes

- **Contract test** (`tests/test_contract.py`): the student must return the teacher encoder's exact output structure.
- **Preprocessing** is checked bit-for-bit against SAM 2's own video loader (`tests/test_frames.py`).
- **No data leakage:** training uses DAVIS 2017 *train* only; the distillation validation set is 6 train videos held out *by video*; DAVIS 2017 val is used only for the final J&F.
- **Training details** found by smoke tests: the random FPN neck is initialised at a small scale (the untrained student's features were ~1000× larger than the teacher's), and BatchNorm statistics are frozen (with micro-batches of 2 they collapsed and broke evaluation).
- Every reported number comes from an MLflow run with its full config and git commit; runs with uncommitted changes are not reported.

## Related work

MobileSAM, EdgeSAM, EfficientTAM and EdgeTAM also make SAM / SAM 2 lighter. EdgeTAM in particular shows that SAM 2's memory attention is a major latency bottleneck on device — consistent with the profiling above.
